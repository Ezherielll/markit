# AGENTS.md

Flutter app **MarkIt** (package `markit`, repo `Ezherielll/MarkIt`, local dir `markit`) — document → Markdown converter. Desktop (Windows/macOS/Linux) **and** web; NOT a mobile app. Dart SDK `^3.12.2`, version `1.2.0+1`.

## Commands

```sh
flutter pub get
flutter analyze          # run after any change
flutter test             # 325 tests; also runs goldens (must stay green)
flutter test --update-goldens test/widget/screenshot_golden_test.dart   # regen goldens
flutter build windows --release    # exe: build\windows\x64\runner\Release\markit.exe
flutter build web --release --base-href /markit/   # --base-href /markit/ is REQUIRED
dart run benchmark/make_corpus.dart    # one-time corpus gen
dart run benchmark/run_corpus.dart     # corpus eval
dart run benchmark/run_benchmark.dart  # perf decision gate (800 pages)
dart run tool/check_complexity.dart    # cognitive complexity gate (≤ 15)
```

- **Windows local build needs Rust** (`super_native_extensions` → cargokit): `winget install --id Rustlang.Rustup -e`, then `flutter clean && flutter pub get && flutter build windows --release`. CI runners have Rust preinstalled. See docs/desktop-release.md.

- After regenerating goldens, copy the changed PNGs from `test/widget/goldens/` to `screenshots/` (README embeds them).
- Integration tests are `@Tags(['desktop'])` (pdfrx/PDFium needs a real platform); everything else runs on any host.
- Golden test setup stubs irondash/super_native_extensions channels (`test/widget/screenshot_golden_test.dart`) — preserve that mocking when touching it.

## Git flow (non-negotiable)

- Work on `develop`. Merge to `master` with `--no-ff` and message `Merge branch 'develop' — <short desc>`, then push **both** branches.
- Pushing `master` triggers **Deploy Web** (GitHub Pages) — but only when `lib/**`, `web/**`, `pubspec.yaml`, `pubspec.lock`, or `deploy-web.yml` changed. README/docs-only changes don't redeploy.
- Commit messages: conventional prefixes (`feat:`, `fix:`, `docs:`, `test:`, `ci:`, `chore:`), written in English.
- Releases: bump `version:` in pubspec.yaml → merge develop → master (`--no-ff`, message `Merge branch 'develop' — <desc>` with an em-dash) → push both branches → tag **from master** while on master: `git tag -a v1.3.0 master -m "MarkIt v1.3.0"` → GATE: `git describe --tags --exact-match master` must print the tag (never push a tag whose commit isn't master's tip) → `git push origin v1.3.0` → CI builds Windows ZIP / macOS DMG (arm64 only) / Linux tar.gz and creates a **draft** release. You must publish the draft manually: `gh release edit v1.3.0 --draft=false`.
- Tag names must NOT end in `-web` (reserved for web milestones; the release workflow excludes them via `if: "!endsWith(github.ref_name, '-web')"`).

## Architecture (what filenames don't reveal)

- `lib/core/` — pure Dart, zero Flutter dependency, fully unit-tested. PDF path: `pdf_source → line_grouper → paragraph_joiner → structure_classifier → doc_stats → converter → output`. Multi-format path: `input_format → extractor → extractors/{csv,docx,pdf,epub,odf,pptx,rtf,xlsx,registry} → markdown_writer`; `format_catalog.dart` is the single source of truth (8 format families word/powerpoint/excel/opendocument/rtf/epub/csv/pdf; legacy OLE2 `.doc/.ppt/.pps/.pot/.xls/.xlsb` detected-but-unsupported gracefully).
- `lib/isolate/` — execution routing via conditional imports: desktop = persistent background isolate (`isolate_executor` + `convert_isolate`), web = inline main isolate. `conversion_controller` = batch queue/cancel/probe.
- **pdfrx/PDFium constraints:** not safe to spawn/teardown repeatedly in one process → ONE persistent worker for the whole batch, probe only before first worker. pdfrx has NO fontSize API → line-height is used as the font-size proxy.
- Supported formats: `pdf, word, powerpoint, excel, opendocument, rtf, epub, csv` convertible; legacy OLE2 formats detected with graceful "not supported yet".
- Web vs desktop: desktop = files on disk (`PdfInput.path`), output written as `.md`; web = bytes in memory (`PdfInput.bytes`), output downloaded via Blob (`lib/ui/download_text_web.dart`; desktop variant is a no-op stub).
- UI: `lib/ui/screens/home_screen.dart` — two panels (DocumentViewer flex 3 + 320px sidebar). Strings are hardcoded in `lib/i18n/strings.dart` (English; NO ARB/l10n generation). Theme persisted via `shared_preferences`. Fonts bundled as assets (Fraunces/Inter/JetBrainsMono) — the app is 100% offline by design.
- Markdown rendering uses **`flutter_markdown_plus`** (`^1.0.12`) — NOT `flutter_markdown` (discontinued).
- Branding: logo widget `lib/ui/widgets/markit_mark.dart`; platform icons generated by `tools/generate_icons.ps1` (pure PowerShell System.Drawing — pwsh C# Add-Type with System.Drawing fails).

## CI gotchas (hard-earned)

- `actions/deploy-pages@v4` **hard-caps its timeout at 600000 ms (10 min)** — passing a larger `timeout:` only emits a warning. Keep `concurrency.cancel-in-progress: false` for the pages group.
- GitHub Pages deployments can get stuck in `deployment_queued` / reject with "in progress deployment" — a GitHub-side issue (`actions/deploy-pages#406`), not the workflow. Recovery: delete stuck deployments via `gh api repos/Ezherielll/MarkIt/deployments/<id> -X DELETE`, then re-run.
- In a workflow, `tags:` + `tags-ignore:` on the same `push` event is INVALID — GitHub rejects the whole workflow file. Use per-job `if:` guards instead.
- Web output size is ~47 MB (canvaskit); not a problem, just don't be surprised by long web deploys.
